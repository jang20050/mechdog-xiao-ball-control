# MechDog 공 색 신호등 — XIAO ESP32-S3로 빨간 공 / 파란 공 구별 → 무선으로 MechDog 제어

**Seeed XIAO ESP32-S3 Sense**의 카메라가 **빨간 공과 파란 공을 구별**하고, 판단 결과를 **무선(ESP-NOW)** 으로
**Hiwonder MechDog**에 보냅니다. MechDog은 **빨간 공을 보면 정지, 파란 공을 보면 전진**합니다.
공의 색은 PC 웹페이지에서 화면 속 공을 클릭해 XIAO에 직접 학습시킵니다.

```
 ┌──────────── PC ────────────┐   USB (COM6)   ┌────── XIAO ESP32-S3 Sense ──────┐   ESP-NOW 무선    ┌──────── MechDog ────────┐
 │ 학습 웹 http://localhost:8000│ ◀────────────▶ │ OV3660 카메라 → 색 판단 (11fps) │ ~~~~~~~~~~~~~~▶ │ 빨간 공 → 정지 (빨간 눈) │
 │ 화면 보기 · 공 클릭 → 학습   │  시리얼 명령    │ 학습값은 내부 NVS 에 저장        │  채널 1, 10바이트 │ 파란 공 → 전진 (초록 눈) │
 └─────────────────────────────┘                └─────────────────────────────────┘                  └──────────────────────────┘
        (학습할 때만 필요)                            (전원만 있으면 단독 동작)                          (AI 비전 모듈은 그대로 장착)
```

| 공 | XIAO 판단 | MechDog 동작 | 눈 색 |
|---|---|---|---|
| 🔴 빨간 공 | `1` (red) | 정지, 공이 사라져도 계속 정지 | 빨강 |
| 🔵 파란 공 | `2` (blue) | 전진, 공이 사라져도 계속 전진 | 초록 |
| 없음 | `0` | 마지막 명령 유지 | - |

## 1. 하드웨어

| 부품 | 역할 | 연결 |
|---|---|---|
| Seeed XIAO ESP32-S3 Sense (OV3660 카메라, 8MB PSRAM) | 공 색 판단 + 무선 송신 | PC USB (COM6) 또는 충전기·보조배터리 |
| Hiwonder MechDog (ESP32, MicroPython 1.21) | 무선 수신 → 보행 | 자체 배터리, 개발 시 USB (COM7, CH340) |
| MechDog 머리 초음파 센서 | 장애물 안전 정지 + 눈 LED | MechDog IIC(1) 0x77 |
| PC (Windows) | 공 색 학습 웹 | Python 3 + pyserial |

XIAO와 MechDog 사이에는 **선이 없습니다.** MechDog에 원래 달린 AI 비전 모듈(IIC(2) 0x53)은 그대로 둬도 됩니다.

## 2. 폴더 구조

```
xiao_ball_eye/xiao_ball_eye.ino   XIAO 펌웨어 (Arduino): 카메라 색 검출 + ESP-NOW 송신 + PC 시리얼 명령
mechdog/ball_command.py           MechDog 프로그램 (MicroPython, 보드에 main.py 로 업로드)
pc_web/server.py                  PC 학습 웹 서버 (Python 표준 라이브러리 + pyserial)
pc_web/index.html                 학습 웹페이지
```

## 3. 빠른 시작

### 3-1. XIAO 펌웨어 올리기
Arduino ESP32 코어 3.x 필요 (3.3.12에서 시험).
```bash
arduino-cli compile -b esp32:esp32:XIAO_ESP32S3:PSRAM=opi --output-dir build xiao_ball_eye
arduino-cli upload  -b esp32:esp32:XIAO_ESP32S3:PSRAM=opi -p COM6 --input-dir build xiao_ball_eye
```
Arduino IDE라면 보드 `XIAO_ESP32S3`, **PSRAM: OPI PSRAM** 으로 설정하세요 (PSRAM을 꺼 두면 카메라 프레임 버퍼를 못 잡습니다).

### 3-2. MechDog 프로그램 올리기
```bash
pip install mpremote
python -m mpremote connect COM7 resume cp mechdog/ball_command.py :main.py
```
MechDog을 껐다 켜면 `main.py` 가 자동 실행됩니다.

### 3-3. 공 색 학습 (PC)
```bash
pip install pyserial
python pc_web/server.py COM6 8000
```
브라우저에서 **http://localhost:8000**

1. **빨간 공 학습** 선택 → 화면 속 빨간 공을 3~5번 클릭 (거리·각도·조명을 바꿔 가며)
2. **파란 공 학습** 선택 → 파란 공도 똑같이
3. **인식 화면** 으로 바꿔서 공만 색칠되는지 확인. 배경이 칠해지면 채도·밝기 슬라이더를 올림
4. **저장** → XIAO 내부(NVS)에 저장되어 전원을 꺼도 유지

### 3-4. PC 없이 실행
학습·저장이 끝나면 XIAO를 PC에서 빼고 USB 충전기·보조배터리(또는 BAT 패드의 3.7V 리튬 배터리)로 전원만 주면 됩니다.
MechDog 전원을 켜면 눈 색으로 상태를 알려 줍니다.

| 눈 색 | 상태 |
|---|---|
| 보라 | XIAO 신호 없음 (1초 이상) → 정지 |
| 파랑 | 신호 받는 중, 아직 공 명령 없음 |
| 초록 | 파란 공 → 전진 중 |
| 빨강 | 빨간 공 → 정지 |
| 주황 | 전진하려 했지만 앞 25cm 안에 장애물 → 대기 |

## 4. 구현 방법

### 4-1. XIAO: 색으로 공 구별하기 (`xiao_ball_eye.ino`)

딥러닝 모델 대신 **학습된 HSV 색 범위**로 판단합니다. 빨강/파랑처럼 색이 분명한 공은 이 방법이 가볍고 빠르며
ESP32-S3에서 초당 약 11프레임으로 동작합니다.

1. **카메라 입력**: OV3660을 QVGA(320×240) **RGB565** 로 받음 (PSRAM 프레임 버퍼 2개, 항상 최신 프레임)
2. **픽셀 검사**: 2픽셀 간격(160×120 = 19,200개)으로 RGB → **HSV** (정수 연산) 변환
3. **색 모델**: 클래스마다 `색상 중심 hc ± 폭 tol`, `채도 ≥ smin`, `밝기 ≥ vmin`
   - 색상은 0~359° 원형이라 빨강(350°~10°)처럼 0°를 넘는 범위도 원형 거리로 비교
4. **면적 판정**: 빨강/파랑 픽셀 수가 `최소 크기(minArea)` 이상이면 그 공이 보인다고 판단.
   **빨강(정지)이 항상 우선**
5. **흔들림 방지**: 같은 결과가 2프레임 연속이어야 판단 변경, 공이 사라진 건 4프레임 연속이어야 인정
6. **무선 송신**: 매 프레임 ESP-NOW 브로드캐스트

### 4-2. 색 학습 원리

웹에서 공을 클릭하면 XIAO가 그 좌표 주변 **9×9 픽셀**을 읽어서:
- 회색/검정(채도 < 40, 밝기 < 25) 픽셀은 버림
- 색상의 **원형 평균**(cos/sin 평균)으로 중심 `hc` 계산, 가장 먼 픽셀까지의 거리 + 6°로 폭 `tol` 계산 (10~40°)
- `smin` = 최소 채도 × 0.7, `vmin` = 최소 밝기 × 0.55 (그늘진 부분도 잡히도록 여유)
- 두 번째 클릭부터는 기존 범위와 새 범위를 **둘 다 덮는 가장 짧은 원호**로 합침 → 여러 조명·거리 조건을 누적 학습

> 안전장치: **파란 공(=전진)은 학습하기 전에는 절대 인식하지 않습니다.** 처음 시험할 때 기본 파랑 범위에
> 배경 일부가 잡히는 것을 확인했기 때문에, 잘못 전진하지 않도록 했습니다. 빨강(=정지)은 기본값으로도 동작합니다.

### 4-3. 무선 통신: ESP-NOW

공유기 없이 ESP32끼리 직접 주고받는 Espressif의 무선 방식입니다. 연결 과정이 없어 지연이 짧고,
MechDog의 MicroPython 1.21 펌웨어에 `espnow` 모듈이 들어 있어 그대로 사용했습니다.

- XIAO: Wi-Fi STA 모드, **채널 1**, 브로드캐스트 주소(FF:FF:FF:FF:FF:FF)로 송신
- MechDog: STA 활성화 + 채널 1, `espnow.irecv(0)` 로 쌓인 패킷 중 **가장 최근 것**만 사용

패킷 (10바이트)

| 바이트 | 내용 |
|---|---|
| 0~3 | `"BEYE"` (이 프로젝트 패킷 표시) |
| 4 | 판단: 0 = 없음, 1 = 빨간 공, 2 = 파란 공 |
| 5 | 신뢰도 0~100 % |
| 6, 7 | 공 중심 x, y (화면 대비 %) |
| 8 | 공 크기 (화면 대비 ‰) |
| 9 | 프레임 번호 (0~255 순환) |

### 4-4. MechDog: 받은 판단으로 걷기 (`ball_command.py`)

```
            파란 공                      빨간 공
  대기 ───────────────▶ 전진 ◀──────────────▶ 정지
(파랑 눈)   mechdog.move(70, 0)        mechdog.move(0, 0)
              │  ▲
   장애물 <25cm│  │ >35cm (0.5초)
              ▼  │
            장애물 대기 (주황 눈)

  어느 상태든 XIAO 신호가 1초 끊기면 → 정지 (보라 눈)
```
- 50ms마다 패킷 확인. 신뢰도 20% 미만 판단은 무시
- `move()` 는 상태가 바뀔 때만 호출 (걷기 명령을 반복해서 보내지 않음)
- 눈 LED(초음파 센서 RGB)도 색이 바뀔 때만 I2C로 전송
- 보폭 `STRIDE`, 직진 보정 `TRIM`, 장애물 거리 `STOP_CM`/`CLEAR_CM` 은 파일 맨 위에서 조정

### 4-5. PC 학습 웹 (`pc_web/`)

브라우저 ↔ `server.py` (HTTP) ↔ XIAO (USB 시리얼). XIAO에는 Wi-Fi AP나 웹서버를 띄우지 않고,
PC가 시리얼 명령으로 화면과 상태를 받아 옵니다.

| 시리얼 명령 | 의미 | 응답 |
|---|---|---|
| `F0` / `F1` | 현재 화면 JPEG / 인식 화면(빨강·파랑으로 칠한 화면) | `@F <길이>\n` + JPEG |
| `S` | 상태 JSON (판단, 픽셀 수, 박스, fps, 색 모델, 무선 전송 횟수) | `@J <길이>\n` + JSON |
| `L c x y` | (x, y) 색을 c(0 = 빨강, 1 = 파랑)로 학습 | `@J` |
| `T c hc tol smin vmin` | 색 범위 직접 설정 (슬라이더) | `@J` |
| `A n` | 최소 크기 설정 | `@J` |
| `R c` | 해당 색 초기화 | `@J` |
| `W` | NVS에 저장 | `@J` |

- 응답 앞에 `@종류 길이` 헤더를 붙여 JSON과 JPEG(바이너리)를 같은 시리얼로 안전하게 주고받음
- PC 서버는 한 번에 한 명령만 보내도록 잠금(lock), 끊기면 자동 재연결
- 시리얼을 열 때 DTR/RTS를 건드리지 않음 (XIAO가 리셋되지 않도록)
- 웹은 화면 한 장을 받으면 바로 다음 장을 요청하는 방식 (약 7~10fps), 상태는 0.4초마다 갱신

**YOLO 자동 학습 (선택)**: `ultralytics` 가 있으면 YOLO26n이 화면에서 공(COCO `sports ball`)을 찾고,
공 안쪽 5지점을 자동으로 학습시킵니다. 실제 주행 판단은 XIAO의 색 판단이 하고, YOLO는 학습 보조로만 씁니다.

## 5. 개발 과정 메모

1. **처음 설계: XIAO를 MechDog에 I2C로 직접 연결 + 휴대폰 웹 학습**
   - XIAO를 I2C 슬레이브(0x52)로 만들고 XIAO가 Wi-Fi AP를 띄워 휴대폰으로 학습하는 방식까지 구현·시험했습니다.
   - XIAO는 PC에 연결해 두고 판단 신호만 무선으로 보내고, 학습은 PC 웹에서 하는 쪽으로 요구사항이 바뀌어 지금 구조로 변경했습니다.
2. **무선 방식 선택**: MechDog 펌웨어에서 `network`, `espnow`, `socket`, `bluetooth` 모듈을 확인 → 공유기가 필요 없는 **ESP-NOW** 선택
3. **학습 방식**: 빨강/파랑 공은 색만으로 충분히 구별되므로, 기기 안에서 빠르게 도는 **HSV 색 범위 학습**을 사용
4. **YOLO26 시도**: 공 위치를 자동으로 찾는 학습 보조로 넣었지만, 개발 PC의 Windows 스마트 앱 컨트롤이
   PyTorch DLL(`torch_python.dll`)을 차단해서 이 PC에서는 실행되지 않았습니다. (클릭 학습에는 영향 없음)
5. **MechDog 업로드 문제**: 보드에서 `main.py` 가 돌고 있으면 `mpremote cp` 가 `could not enter raw repl` 로
   실패하는 경우가 있었습니다 → `resume` 옵션 사용, 또는 raw REPL로 직접 파일을 나눠 쓰는 방식으로 해결

## 6. 시험 결과

| 항목 | 결과 |
|---|---|
| XIAO 카메라 / 색 검출 속도 | OV3660, 약 11 fps |
| 시리얼 화면 전송 | QVGA JPEG 약 2~3 KB, 한 장 약 0.1초 |
| ESP-NOW 송신 | 매 프레임 송신, 송신 실패 0회 |
| MechDog 무선 수신 | 재시작 후 바로 `XIAO 신호 받음` |
| 전체 흐름 (판단 → 무선 → MechDog) | 빨간색 범위를 일부러 넓혀 "빨간 공" 판단을 만들었을 때 MechDog 로그에 `빨간 공 (신뢰도 100%) → 정지` 확인 |
| 실제 빨간/파란 공으로 주행 | 아직 시험 전 |

## 7. 문제 해결

| 증상 | 확인할 것 |
|---|---|
| 학습 웹에 "XIAO 연결 안 됨" | COM 포트 번호, 다른 프로그램(Arduino 시리얼 모니터)이 COM6을 쓰고 있지 않은지 |
| MechDog 눈이 계속 보라색 | XIAO 전원, 두 기기 거리, 양쪽 채널(1) 일치 여부 |
| 파란 공에 반응 없음 | 파란 공을 학습했는지, **저장**했는지 (학습 전 파랑은 인식 안 함) |
| 배경이 공으로 인식됨 | 인식 화면에서 확인 → 채도·밝기 올리기, 최소 크기 올리기, 색상 폭 줄이기 |
| 멀리 있는 공을 못 봄 | 최소 크기 낮추기 |
| `could not enter raw repl` | 다시 시도, 또는 MechDog 전원을 껐다 켠 직후 업로드 |
